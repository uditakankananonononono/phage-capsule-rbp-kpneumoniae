# Pending private Actions CPU timing pilot

Prepared but **not dispatched**. One manually triggered workflow only, `.github/workflows/esm-cpu-timing-pilot.yml`, `ubuntu-24.04`, four vCPU/16 GB RAM standard private runner. Job hard timeout 25 minutes, internal inference cap 17 minutes, one concurrent group, `contents: read`, one-day artifact retention. No push trigger. On failure or timeout only completed partial timing data are checkpointed; no extrapolation if fewer than nine references complete. It fetches only public Zenodo author `RBPbase.csv` with MD5 check, loads official `esm2_t33_650M_UR50D` with SHA-256 `ea9d0522b335a8778dea6535a65301f10208dece28cd5865482b0b1fc446168c`, and times nine fixed, outcome-blind protein embeddings in three length bands, including 1300-1477 aa. There is **no generative operation, no host-range score and no safety claim**. The output is runtime and peak process RSS per protein, not a design.

The workflow cannot run until explicitly dispatched. It was deliberately made `workflow_dispatch`-only so committing the plan does not consume private runner minutes. Before dispatch: owner approval for spending included credits, verification no paid overage, and a method to inspect the run, artifact and minute accounting. The job's maximum theoretical run is 25 runner-minutes if one standard Linux job starts; dependency/setup overhead is included in that 25. This is below the earlier 200-minute cap but remains a wallet-bearing credit use. Actual billable usage may round up; obtain it from account usage if available and otherwise label observed job duration only.

Official limits and billing: https://docs.github.com/en/actions/reference/limits ; https://docs.github.com/en/actions/reference/runners/github-hosted-runners ; https://docs.github.com/en/billing/concepts/product-billing/github-actions . Current repository is private, so public-repo unlimited use does not apply.
